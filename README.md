# Личный кабинет ученика KIBERone Караганда

Мобильный сайт для учеников школы программирования. Ученик входит логином и паролем, которые выдаёт школа, и видит только свой кабинет: кибероны, уроки, задания, тесты, грамоты, ссылку на портфолио и папку Google Диска. Преподаватель заводит учеников, сбрасывает пароли и запускает синхронизацию с AlfaCRM.

Самостоятельной регистрации нет.

## Что уже работает

- Вход ученика и преподавателя, пароли хранятся как bcrypt-хеш.
- После нескольких неудачных попыток вход блокируется на 15 минут.
- Ученик не открывает чужой кабинет и панель преподавателя.
- Преподаватель создаёт, правит и удаляет учеников, выключает аккаунт, задаёт логин и новый пароль.
- Импорт CSV и экспорт списка.
- Кибероны, имя, группа, уроки, посещаемость, темы, задания с уроков и тесты подтягиваются из AlfaCRM.
- Если ключа CRM нет, кабинет работает в демо-режиме на вымышленных учениках.
- Грамоты и достижения хранятся в PostgreSQL и отдаются только владельцу или преподавателю.
- Приложение ставится на телефон как PWA: есть манифест и service worker.

## Запуск у себя

Нужны Node.js 22, npm и Docker (для локальной PostgreSQL).

```bash
cp .env.example .env
docker compose up -d db
npm install
npx prisma migrate deploy
npm run db:seed
npm run dev
```

Сайт откроется на [http://127.0.0.1:4317](http://127.0.0.1:4317). База — PostgreSQL в Docker, грамоты лежат в ней же.

Проверка сборки:

```bash
npm test
npm run lint
npm run build
npm start
```

## Переменные окружения

Файл `.env` не коммитьте. Образец — `.env.example`.

| Переменная | Зачем |
| --- | --- |
| `DATABASE_URL` | Строка PostgreSQL. Локально `postgresql://cabinet:cabinet@127.0.0.1:5432/cabinet`. На Render подставляется сама. |
| `ALFACRM_HOST` | Хост без схемы: `kiberonekaraganda.s20.online`. |
| `ALFACRM_EMAIL` | Почта отдельного пользователя CRM только для API. |
| `ALFACRM_API_KEY` | Ключ API v2 из «Мой профиль» в AlfaCRM. Пока ключа нет, оставьте пустым. |
| `ALFACRM_BRANCH_ID` | Филиал Караганды. Проверено на живой CRM: `1`. |
| `ALFACRM_MOCK` | `1` — всегда демо, даже если ключ заполнен. На Render так и стоит, пока ключ не включат. |
| `ALFACRM_BONUS_FIELD` | Необязательно. Запасное имя поля, если `balance_bonus` в карточке пустой. |
| `ADMIN_LOGIN` / `ADMIN_PASSWORD` | Первый вход преподавателя. Если учётка уже есть, а переменная пустая или не задана, seed её не трогает. Сменить пароль можно в панели: «Сменить пароль». |
| `SEED_DEMO` | `0` на боевом сайте: не создавать Алису, Тимура, Миру и Леру. |
| `CRON_SECRET` | Секрет для ручного запроса синхронизации. На Render генерируется сам. |
| `SYNC_INTERVAL_MINUTES` | Как часто сам процесс ходит в CRM. На бесплатном Render стоит `0`: сайт засыпает, таймер ненадёжен. На платном — `360`. |
| `SYNC_MAX_AGE_HOURS` | Если последняя успешная синхронизация старше этого числа часов, она запускается при входе ученика или преподавателя. `0` выключает это. По умолчанию 6. |
| `SHOW_DEMO_LOGINS` | `1` — показать учебные логины. На Render стоит `0`. |

Живой режим включается, только когда заполнены все четыре поля `ALFACRM_HOST`, `ALFACRM_EMAIL`, `ALFACRM_API_KEY` и `ALFACRM_BRANCH_ID`, и `ALFACRM_MOCK` не равен `1`.

Ключ API берётся так: в AlfaCRM наведите на правый верхний угол → «Мой профиль» → поля «E-mail» и «Ключ API (v2api)». У этого пользователя должна быть роль с доступом к модулю v2api и к нужному филиалу. Личный аккаунт сотрудника лучше не использовать.

## Как завести ученика

Кабинет сам не импортирует всех учеников из AlfaCRM. Преподаватель добавляет их по одному. Синхронизация обновляет только тех, кто уже есть в кабинете, и никого не создаёт.

1. Войдите как преподаватель.
2. Откройте «Из AlfaCRM». Введите ID клиента или часть имени и нажмите «Найти». Поиск читает только действующих учеников (`is_study: 1`).
3. Проверьте карточку и нажмите «Добавить в кабинет». Кабинет заберёт имя из CRM, придумает логин и пароль и сразу подтянет кибероны и занятия этого ученика. В AlfaCRM ничего не записывается.
4. Логин и пароль покажутся один раз. Запишите их и отдайте ученику или родителю. В базе остаётся только хеш.
5. Если нужно завести вход без поиска в CRM, откройте «Новый ученик» и заполните имя, логин, пароль и id клиента вручную. Затем нажмите «Синхронизировать».

Выключить кабинет: в карточке ученика снимите «Можно входить в кабинет». Сессии этого ученика сразу сбрасываются. В CRM его карточка не меняется.

Забыли пароль — преподаватель задаёт новый в той же карточке. Сам ученик пароль не меняет.

### CSV

Шаблон: `/students-template.csv` в запущенном сайте. Колонки:

`login,password,fullName,alfacrmId,groupName,portfolioUrl,driveUrl,isActive`

- Новый логин без пароля пропускается.
- Существующий логин обновляется. Пустой пароль пароль не меняет.
- `isActive`: `1` или `0`.
- Экспорт: в панели пункт «Импорт CSV» → «Экспорт учеников». Пароли в файл не попадают.

## Синхронизация AlfaCRM

Три способа, они не мешают друг другу:

1. Кнопка «Синхронизировать сейчас» в разделе «Синхронизация» и такая же кнопка в карточке ученика. Срабатывает сразу, даже если сайт только что проснулся.
2. Ленивая синхронизация при входе. Если последняя успешная синхронизация старше `SYNC_MAX_AGE_HOURS` (по умолчанию 6 часов), вход ученика или преподавателя запускает её в фоне и не заставляет ждать. На бесплатном Render это основной способ: сайт засыпает через 15 минут, и внутренний таймер вместе с ним останавливается.
3. Внутренний таймер `SYNC_INTERVAL_MINUTES`. Имеет смысл только на платном тарифе, где процесс не засыпает. На пробном запуске он выключен (`0`).

Плановый запуск снаружи, если задан `CRON_SECRET`:

```bash
curl -X POST -H "Authorization: Bearer ВАШ_CRON_SECRET" https://ваш-домен/api/cron/sync
```

Пример cron раз в 6 часов:

```cron
0 */6 * * * curl -fsS -X POST -H "Authorization: Bearer ВАШ_CRON_SECRET" https://ваш-домен/api/cron/sync
```

На платном тарифе `SYNC_INTERVAL_MINUTES=360` добавляет обход раз в 6 часов, даже если никто не входил. У AlfaCRM лимит 5 запросов в секунду, клиент выдерживает паузу между запросами. Токен живёт час и кэшируется. При ответе 401 токен запрашивается ещё один раз.

Ручной запуск из консоли: `npm run sync`.

### Какие методы API используются

Документация: [REST API Альфа CRM](https://alfacrm.pro/usefull/integrations/integration/api). Все вызовы — `POST` и JSON. Токен передаётся заголовком `X-ALFACRM-TOKEN`.

| Зачем | Метод |
| --- | --- |
| Токен | `POST /v2api/auth/login` с телом `{ "email", "api_key" }` |
| Карточка ученика: имя, статус, `balance_bonus` | `POST /v2api/1/customer/index` с `is_study: 1`. Без `is_study: 1` этот ключ возвращает только лиды |
| Баланс киберонов | Поле `balance_bonus` в карточке клиента. Если его нет — `POST /v2api/1/bonus/balance-bonus?customer_id={id}` |
| История бонусов | `POST /v2api/1/bonus/index` — на ключе школы отвечает 404, поэтому начисления берутся из `lesson.details[].bonus` |
| Группы ученика | `POST /v2api/{branch}/cgi/customer?customer_id={id}`, затем `POST /v2api/{branch}/group/index` |
| Уроки | `POST /v2api/{branch}/lesson/index` отдельно для статусов 1, 2 и 3 |
| Предметы и статус обучения | `subject/index`, `study-status/index` |
| Тесты | `POST /v2api/{branch}/test-result/index` |

Кибероны — это бонусный счёт клиента, вкладка «Бонусы». На живой CRM школы поле `balance_bonus` есть прямо в карточке клиента, его и берём. `bonus/index` на этом ключе отвечает 404, поэтому список начислений строится из поля `bonus` в деталях проведённого урока. Списания в магазин в этот список не попадают: их вносит преподаватель. Кабинет ничего не пишет в CRM.

Филиал внутри Караганды («Гоголя» или «Стр») не приходит отдельным полем. Он вычисляется из названия группы: если в названии есть «Гоголя» — филиал Гоголя, если есть «Стр» — филиал Стр. `ALFACRM_BRANCH_ID` при этом равен `1`: это филиал CRM целиком, а не площадка.

Урок без параметра `status` в API считается проведённым, поэтому статусы запрашиваются явно: `1` запланирован, `2` отменён, `3` проведён. «Были / не были» берётся из `details[].is_attend` для этого `customer_id`. Тема — поле `topic`. Домашнее задание урока — поле `homework`.

Окно уроков: 400 дней назад и 120 дней вперёд.

### Чего в API нет — это заполняет преподаватель

- Ссылка на портфолио.
- Ссылка на личную папку Google Диска и подпись папки именем ученика. Папку кабинет сам не создаёт: нужен доступ к Google Workspace, его в задаче нет.
- Грамоты, файлы и достижения.
- Рейтинг группы. В CRM такого справочника нет. В кабинете он необязательный: преподаватель включает его и ставит балл. Ученик видит имена и баллы своей группы, чужой кабинет при этом не открывается.
- Отдельные домашние задания, которых нет в поле `homework` урока.
- Результаты тестов, если метод `test-result` недоступен роли API (в правах CRM это `v2api.test-result`).

Правка урока, пришедшего из CRM, помечается «правка школы» и не затирается следующей синхронизацией, пока не нажать «Снова брать из CRM».

Ручной баланс: если включить «Не перезаписывать баланс из CRM», цифра на главной остаётся школьной. Иначе цифра берётся из `balance_bonus`.

## Публикация на Render

Сначала месяц без карты, файл `render.yaml`: сайт и Postgres на плане `free`. Потом, не позже 30-го дня, переход на `render.paid.yaml` без переноса данных. Грамоты уже лежат в Postgres, отдельный диск не нужен.

Бесплатный сайт засыпает через 15 минут без заходов и просыпается около минуты. На один аккаунт 750 бесплатных часов в месяц: пока сайт спит, часы не тратятся. Бесплатная Postgres одна на аккаунт, 1 ГБ, без резервных копий Render. Она истекает через 30 дней после создания. Потом ещё 14 дней можно перейти на платный план и сохранить данные. После этих 14 дней Render удаляет базу вместе с учениками и грамотами. Письма об этом приходят на почту аккаунта, но день лучше отметить в календаре сразу.

Другие бесплатные площадки для этого кабинета хуже: Railway Free засыпает и даёт $1 использования, Koyeb Free засыпает и держит базу 5 часов в месяц, Fly.io Developer Postgres засыпает через 15 минут, Vercel Hobby с Neon Free — это два аккаунта и нет постоянно работающего Node.

Платный Render, цены на ноябрь 2026:

- сайт `0.5c-512mb` — $7
- Postgres `0.1c-256mb` — $6
- диск базы 1 ГБ — $0.30

Итого около **$13.30** в месяц. Карта нужна только в момент перехода.

### Откуда Render берёт код

Blueprint, который создаёт и сайт, и базу, умеет брать репозиторий только у подключённого Git-провайдера. Просто вставить адрес Git не получится: так Render поднимает один сайт, но не базу из `render.yaml`.

Поддерживаются GitHub, GitLab, Bitbucket и Cursor Origin (бета). Войти в Render через Cursor Origin нельзя, только через почту, GitHub, GitLab или Bitbucket.

Самый прямой путь для этого проекта — Cursor Origin, потому что код уже лежит там:

1. Владелец школы регистрируется на [https://render.com](https://render.com) по почте. Карту не привязывает.
2. В Render: Account Settings → Git Deployment Credentials → Add credential → Cursor Origin.
3. Если Render ещё не установлен в рабочем пространстве Cursor, это может сделать только администратор этого пространства: в том же окне выбрать Install on Cursor и подтвердить установку. Если приложение уже стоит, достаточно Connect.
4. New → Blueprint, выбрать этот репозиторий. Путь к файлу оставить `render.yaml`, ветка `main`.

Если подключить Origin не получается, запасной путь — GitHub. Создайте репозиторий, залейте туда проект, войдите в Render через GitHub и снова выберите New → Blueprint. Для приватного репозитория GitHub установите приложение Render и дайте ему доступ к этому репозиторию.

### Что нажать при создании

1. Render спросит секреты из `render.yaml`. Впишите `ADMIN_PASSWORD` — пароль преподавателя, не короче 8 символов.
2. `ALFACRM_EMAIL` и `ALFACRM_API_KEY`: пока ключа нет, поставьте прочерк `-`. Живой режим выключен (`ALFACRM_MOCK=1`), прочерк никуда не уйдёт.
3. Deploy Blueprint. Первый запуск создаст базу, применит миграции и заведёт вход `admin`. Учебных учеников не будет (`SEED_DEMO=0`).
4. Откройте адрес вида `https://kiberone-cabinet.onrender.com`. Первый заход после паузы может идти около минуты: сайт просыпается. Войдите как `admin`.
5. Добавьте учеников по одному через «Из AlfaCRM». Кнопка «Синхронизировать сейчас» обновляет только тех, кто уже есть в кабинете. Если с прошлой успешной синхронизации прошло больше 6 часов, следующий вход тоже запустит её сам.
6. Когда ключ API будет на руках: Environment → заменить прочерки на почту и ключ, поставить `ALFACRM_MOCK` в `0`, сохранить.

`CRON_SECRET` Render придумает сам. Он нужен, только если синхронизацию дергают снаружи:

```bash
curl -X POST -H "Authorization: Bearer СЕКРЕТ" https://ваш-адрес.onrender.com/api/cron/sync
```

### Переход на платный тариф до 30-го дня

Делайте это в панели, не создавая новую базу. Тот же адрес сайта и те же ученики.

1. Привяжите карту к аккаунту Render.
2. Откройте веб-сервис `kiberone-cabinet` → Settings → Instance Type. Смените Free на `0.5c-512mb` и сохраните.
3. Откройте базу `kiberone-db` → Settings → план. Смените Free на `0.1c-256mb`. Если спросят размер диска, укажите **1 ГБ**, не 15: лишние гигабайты стоят $0.30 каждый, а школе хватает одного.
4. Откройте Blueprint → Settings → Blueprint Path и укажите `render.paid.yaml`. Сохраните. Иначе следующий деплой прочитает `render.yaml` и вернёт оба ресурса на Free.
5. На платном тарифе процесс не засыпает. В `render.paid.yaml` таймер синхронизации включён на 6 часов, плюс остаются кнопка и синхронизация при входе.

Если 30-й день уже прошёл, базу ещё можно поднять тем же переходом плана в течение 14 дней. В эти дни она не открывается, пока план не сменят. Новую бесплатную базу создавать не надо: из истёкшей бесплатной копию снять нельзя, резервных копий у Free нет. После 14 дней данных уже нет.

## Безопасность

- Пароли только в виде хеша, в экспорте паролей нет.
- Сессия — случайный токен в httpOnly-cookie, в базе хранится его sha256. Срок 14 дней.
- Ученик и преподаватель — разные роли. Все запросы ученика фильтруются его id из сессии.
- Файлы грамот лежат в PostgreSQL и не отдаются без входа.
- Заголовки `X-Frame-Options`, `nosniff`, `Referrer-Policy`.
- Сайт закрыт от индексации.

Это не замена юристу: перед запуском школе стоит решить, кто имеет доступ к серверу и как долго хранить файлы грамот.

## Что уже известно и что ещё спросить

Проверено на живой CRM: `branch_id` равен 1, ученики читаются с `is_study: 1`, в карточке есть `balance_bonus`, `bonus/index` отвечает 404. Площадка «Гоголя» или «Стр» берётся из названия группы.

Осталось:

1. Какая почта и ключ API будут у отдельного пользователя CRM, когда школа будет готова их вписать.
2. Нужно ли в рейтинге показывать имена одногруппников или только место самого ученика?
3. Кто создаёт папки на Google Диске и присылает ссылки?
4. Домашние задания всегда пишутся в поле урока в AlfaCRM или их ведут отдельно?
5. Нужен ли ученику свой способ сменить пароль?
